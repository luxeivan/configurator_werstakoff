# Импорт каталога из ZIP

Групповая загрузка товаров вместе с 3D-моделями, фотографиями и свойствами из одного ZIP-архива.
Кнопка **«Импорт ZIP»** — в админке, вкладка «Каталог» (панель «Товары»).

Документация: [формат архива](#формат-архива) · [манифест CSV](#манифест-csv) · [манифест JSON](#манифест-json) ·
[свойства](#свойства-в-манифесте) · [фотографии](#фотографии) · [3D-модели](#требования-к-3d-моделям) ·
[конвертация моделей](#как-конвертировать-модели) · [ограничения](#ограничения) · [примеры](#примеры)

## Как пользоваться

1. Упакуйте единый ZIP-архив: манифест в корне, модели и фото — папками (см. [формат](#формат-архива)).
2. Админка → **Каталог** → кнопка **«Импорт ZIP»**.
3. Выберите `.zip` (до 1000 МБ по умолчанию), при необходимости отметьте «создавать недостающие параметры свойств».
4. «Импортировать» — появится прогресс: распаковка → разбор манифеста → создание/обновление товаров → оптимизация крупных моделей.
5. По окончании — отчёт: создано / обновлено / оптимизировано моделей / список ошибок построчно.
6. Товары с одинаковым `sku` **обновляются** (цена, габариты, свойства, модель заменяются; набор `images` в строке полностью **заменяет** старые фото), без `sku` — всегда создаются новые.

> Маленькие модели (до 15 МБ) сохраняются как есть (с текстурами). Крупные (≥ 15 МБ, настраивается `MODEL_AUTO_OPTIMIZE_MB`)
> после загрузки **автоматически оптимизируются** до ~50 000 треугольников, планировщик берёт лёгкую версию, оригинал сохраняется.

## Формат архива

```
импорт.zip
├── manifest.csv        (или manifest.json / export.json)  ← манифест, имя обязательно
├── models/
│   ├── stol-1.glb
│   ├── telezhka-prf-e.stl
│   └── slf-1200.glb
└── images/
    ├── stol-1.jpg
    └── slf-1200.png
```

- Манифест может называться `manifest.csv`, `manifest.json` или `export.json` (должен лежать в корне архива).
- Пути к моделям и фото в манифесте пишутся относительно корня архива, прямыми слэшами: `models/stol-1.glb`.
- Имена файлов — **латиницей, без пробелов и кириллицы** (`stol-1.glb`, не `Стол 1.glb`). Регистр важен.
- Допустим любой способ создания ZIP (проводник Windows, 7-Zip, `zip -r`, PowerShell `Compress-Archive`).

## Манифест CSV

Файл с заголовками в первой строке, разделитель — запятая. **Кодировка UTF-8** (в Excel: «Сохранить как → CSV UTF-8»).

```csv
sku,section,name,price,width_cm,depth_cm,height_cm,weight_kg,unit,model,images,is_active,color,load,series
STOL-1,Верстаки/Механик,Стол верстачный 2000,49900,200,80,74.4,95,шт,models/stol-1.glb,images/stol-1.jpg,да,RAL 7016;RAL 9003,150,Mechanic
SLF-1200,Стеллажи,Стеллаж SLF 1200,38900,140,80,220,60,шт,models/slf-1200.glb,images/slf-1200.png,да,,
```

Все значения считаются CSV-кодированными: значения с запятыми оберните в кавычки `"…"`, кавычки внутри — двойные `""`.

### Колонки

| Колонка | Обязательна | Описание |
|---|---|---|
| `sku` | да (ключ) | Артикул. Есть в каталоге → товар обновляется, нет → создаётся |
| `section` | нет (по умолчанию «Каталог») | Путь раздела, разделитель `/` или `>`: `Верстаки/Механик`. Дерево создаётся автоматически |
| `name` | да | Наименование товара |
| `price` | нет | Цена в рублях (с десятичной частью): `49900` или `49900.75` |
| `price_kopecks` | нет | Альтернатива: цена сразу в копейках. Если заданы обе — приоритет `price_kopecks` |
| `width_cm`, `depth_cm`, `height_cm` | да | Габариты в см: ширина (X), глубина (Z), высота (Y). Должны соответствовать модели |
| `weight_kg` | нет | Вес, кг |
| `unit` | нет | Единица измерения, по умолчанию `шт` |
| `short_description` | нет | Краткое описание |
| `description` | нет | Полное описание |
| `is_active` | нет | `да/нет`, `1/0`, `true/false`. По умолчанию «да» |
| `model` | нет | Путь к файлу модели внутри архива: `models/stol-1.glb` |
| `images` | нет | Пути к фото через `;` или `|` (или через `;` в CSV). Первое фото — главное |
| `color`, `load`, … | нет | Любая другая колонка = **код/имя свойства** из справочника (см. [свойства](#свойства-в-манифесте)) |

Псевдонимы колонок принимаются: `category`→`section`, `название`→`name`, `ширина`/`глубина`/`высота`, `цена`, `вес`, `описание`, `фото`, `модель` и т.п. Можно также писать свойства с префиксом: `property.color`.

## Манифест JSON

Массив объектов или объект с ключом `products`:

```json
{
  "products": [
    {
      "sku": "STOL-1",
      "section": "Верстаки/Механик",
      "name": "Стол верстачный 2000",
      "price": 49900,
      "widthCm": 200, "depthCm": 80, "heightCm": 74.4,
      "weightKg": 95,
      "model": "models/stol-1.glb",
      "images": "images/stol-1.jpg",
      "isActive": true,
      "color": "RAL 7016;RAL 9003",
      "load": 150,
      "series": "Mechanic"
    }
  ]
}
```

`export.json` — в том же виде (массив объектов или `{"products": [...]}`). Если файл из другого источника имеет другую структуру —
этот документ описывает формат, к которому его нужно привести.

## Свойства в манифесте

Колонка (или ключ объекта) — **код или наименование** существующего свойства справочника («Свойства товаров» в админке):
`color`, `load`, `series`, `brand`, `garant` и т.д.

Значения по типу свойства:

| Тип свойства | Как заполняется |
|---|---|
| `enum`, `color` | Подпись параметра из справочника (`RAL 7016`, `Механик`), для нескольких значений — через `;`. Есть соответствие по подписи (без учёта регистра, `ё→е`), по коду параметра и по HEX (#RRGGBB) |
| `number` | Число (`150`, `4.5`) |
| `boolean` | `да/нет`, `1/0`, `true/false` |
| `string`, `text` | Произвольный текст |

- Если параметр enum/color не найден — значение пропускается, в отчёте появится предупреждение **если не включена опция «создавать недостающие параметры»**.
- При включённой опции недостающий параметр создаётся автоматически (для цветов HEX пишутся в параметр, RAL — в поле RAL).
- Свойства, которых нет в справочнике, игнорируются с предупреждением — справочник ведётся отдельно («Свойства товаров»).

## Фотографии

- **Внутри архива**: `images/stol-1.jpg` — путь в колонке `images`.
- **По URL**: `https://site.ru/img/stol-1.jpg` — скачается автоматически (таймаут 30 с на файл).
- Несколько фото — через `;` или `|`. Первое становится главным (превью товара).
- При обновлении товара по `sku` новый набор фото в строке **заменяет** старые.
- Фото нормализуются: JPEG ≤ 2400 px, белый фон подкладывается, лишнее сжимается (как при ручной загрузке).

## Требования к 3D-моделям

Поддерживаются форматы в ZIP:

| Формат | Расширение | Комментарий |
|---|---|---|
| GLB (glTF 2.0 binary) | `.glb` | ✅ **Рекомендуется.** Один файл: геометрия + материалы + текстуры внутри |
| STL | `.stl` | Binary или ASCII. Только геометрия, материал «сталь» |
| glTF (JSON) | `.gltf` | Только самодостаточный (без внешних `.bin`/текстур). Лучше конвертировать в GLB |

### Что должна содержать модель

1. **Верная геометрия с пропорциями**, соответствующими габаритам товара в манифесте (`width_cm × depth_cm × height_cm`).
   Планировщик масштабирует модель именно под эти габариты — если файл «кривой» или пропорции не совпадают, товар будет выглядеть искажённо.
   Единицы (мм или м) не важны — важны **пропорции**.
2. **Ориентация Y-up** (ось Y — вверх). Это естественно для Blender/glTF; для моделей из CAD в Z-up желательно развернуть (или использовать STL — для STL планировщик переворачивает сам).
3. **Стоит на полу**: низ модели на уровне Y = 0 (если не так — планировщик поставит на пол автоматически, но зеркальные/перевёрнутые варианты лучше выправлять до загрузки).
4. **Материалы PBR** для GLB: `baseColor` + `metallicRoughness`; текстуры встроенные (JPEG/PNG внутри GLB). Металлам лучше низкий `roughness`, тинт можно менять опцией «Цвет».
5. **Не перекрашиваемые детали** (дерево, столешница, чёрные элементы): на их материале поставьте `extras: { tintable: false }` — такие материалы не перекрашиваются при выборе RAL-цвета.
6. **Имя файла** — латиница без пробелов: `stol-1.glb`, не `Стол 1.glb`.

### Бюджет модели

| Параметр | Рекомендация | Предел |
|---|---|---|
| Треугольников | до 100 000 | до ~2 500 000 (импорт не откажет, но лучше не надо) |
| Размер файла | до 15 МБ (сохраняется как есть) | до 500 МБ на файл |
| Файлов по 500 КБ — не проблема | — | — |

Файлы ≥ `MODEL_AUTO_OPTIMIZE_MB` (по умолчанию 15 МБ) после импорта автоматически упрощаются до ~50 000 треугольников
(единый материал «сталь», тонируется RAL) — оригинал с текстурами сохраняется отдельно.

## Как конвертировать модели

### Из Inventor / Компас-3D / SolidWorks / КОМПАС

| Источник | Шаги |
|---|---|
| **Inventor / SolidWorks / Компас** | Экспорт в **STL** (File → Save As → STL, бинарный). Загрузите STL в Blender и конвертируйте в GLB (ниже) |
| **3ds Max** | Плагин Babylon.js glTF Exporter или File → Export → glTF (если установлен). Либо экспорт FBX → Blender → GLB |
| **КОМПАС-3D** | File → Save As → STL (триангуляция с настройкой точности). Либо встроенная «Трёхмерная печать» → STL |

### Через Blender (бесплатно, самый надёжный путь)

1. Blender → File → Import → доведите модель (STL/FBX/STEP/OBJ).
2. Переведите в **метры**: в правой панели (сетка) или `File → Properties…` — Scale: `0.001` если модель в мм, `1` если уже в метрах. Проверьте размер по габаритам (`N` — панель Transform).
3. Поверните так, чтобы ось **Y смотрела вверх** и модель стояла на `Y=0`.
4. Назначьте материалы (при необходимости): базовый металл `(metalness 0.85, roughness 0.35)`. Файлу это не мешает — планировщик всё равно умеет перекрашивать.
5. File → Export → **glTF 2.0**:
   - Format: **glTF Binary (.glb)**;
   - Mesh: включить «Apply Modifiers»;
   - Textures: **JPEG/PNG** (сжать, например до 2048px) — текстуры вшиваются в файл;
   - Animations можно выключить.
6. Проверьте размер файла и переименуйте латиницей без пробелов.

### Онлайн / другие

- Онлайн-конвертеры STEP/STL → GLB (например «Model Converter» от Threekit) — только для разовых файлов, конфиденциальность данных учитывайте сами.
- ВАЖНО: всегда проверяйте результат в планировщике (вкладка 3D): габариты, ориентация, отсутствие пустоты.

## Ограничения

- Максимум **5000 строк** в манифесте.
- Максимальный размер архива — `MAX_IMPORT_ZIP_MB` (по умолчанию **1000 МБ**).
- Один файл модели — до `MAX_MODEL_MB` (по умолчанию **500 МБ**).
- Свойства и параметры справочника не удаляются из-за импорта — только дополняются (при опции создавать параметры).
- Импорт идёт в фоне; страницу можно закрыть — статус и результат будут видны на вкладке при следующем входе
  (статус живёт в памяти процесса: после перезапуска сервера историю нельзя посмотреть, импорт при этом не прерывается,
  только перестаёт быть видимым — запускайте повторно при необходимости).

## Примеры

### Минимум (только товары + модели)

```csv
sku,section,name,price,width_cm,depth_cm,height_cm,model
B-100,Верстаки,Верстак 1000,25900,100,60,85,models/b-100.glb
B-150,Верстаки,Верстак 1500,32900,150,60,85,models/b-150.glb
```

### Полный (свойства + фото + описание)

```csv
sku,section,name,price,width_cm,depth_cm,height_cm,weight_kg,short_description,description,is_active,model,images,color,series,load,garant
G-2000,Верстаки/Grand,Верстак Grand 2000,79900,200,80,74,120,"Усиленная рама","Столешница 30 мм, нагрузка до 300 кг",да,models/g-2000.glb,images/g-2000.jpg;images/g-2000-2.jpg,RAL 7016,Grand,300,5 лет
```
