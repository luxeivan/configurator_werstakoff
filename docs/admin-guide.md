# Руководство администратора

## Вход

Откройте `/login`. Администратор создаётся seed-скриптом из `ADMIN_EMAIL` и
`ADMIN_PASSWORD`; пароль можно сменить через CLI:

```bash
docker compose exec app npm run create-admin -- --email admin@example.ru --password 'новый-пароль' --force
```

Роли:

- **admin** — всё: каталог, свойства, заказы, настройки, пользователи, удаление.
- **manager** — только заказы: список, карточка, статусы, PDF, пересборка. Каталог и
  настройки недоступны (проверяется на сервере).
- **customer** — покупатель; в MVP гостевой checkout, роль оставлена для развития.

## Разделы админки

Вход в `/admin` открывает каталог. Сверху справа — вкладки «Каталог», «Свойства товаров»,
«Настройки», «Заказы»; активная вкладка подсвечена.

## Каталог

`/admin/catalog`:

1. **Разделы** — дерево слева. Создайте раздел, при необходимости вложенный.
   Нельзя удалить раздел с подразделами или товарами; сначала перенесите/удалите их.
2. **Товары** — поиск и список в центре. Кнопка «+» создаёт товар, «Изменить» открывает
   карточку.
3. **Карточка товара**, вкладки:
   - **Основное** — название, SKU, цена в рублях, габариты в см, высота, описание,
     публикация. Цена хранится в копейках, ввод — в рублях.
   - **Изображения** — JPEG/PNG/WebP до 8 МБ; сервер приводит к JPEG 2400 px.
   - **3D-модель** — GLB/GLTF/STL до 50 МБ. Bbox — размеры исходной модели в мм.
     «Рассчитать масштаб» подбирает коэффициент по габаритам карточки. При
     необходимости задайте ручной масштаб, поворот и смещение.
   - **Свойства** — значения из общего справочника.
   - **Опции** — параметры с доплатой; обязательные значения попадут в заказ.

### Справочник свойств

`/admin/properties` или вкладка «Свойства товаров». Свойства уникальны без учёта регистра,
пробелов и «ё» (`Цвет` = `цвет`). Внутри свойства параметры тоже уникальны.
Удалить свойство/параметр, используемый товаром, нельзя — сначала отвяжите его.

### Массовый импорт каталога

Текущий каталог наполнен из `models.zip` и `export.json`:

- 288 GLB-моделей, 289 товаров (включая «Тележку PRF-E»), 35 разделов;
- 183 товара сопоставлены с JSON поставщика: реальные цена, описание, артикул,
  габариты, вес, гарантия, страна, нагрузка, полки, покрытие, RAL и фото;
- 105 моделей без точного совпадения: сгенерированное название, описание
  «3D-модель», цена 0 ₽ («по запросу»). Их нужно найти в прайсе и заполнить вручную;
- 184 фото скачаны с `werstakoff.ru` и привязаны к товарам;
- все модели хранятся в `uploads/public/models/...`, метаданные — в MySQL.

Правила сопоставления: семейство/папка модели → раздел, затем код/артикул и
габариты из имени файла (например, `shelving_light_2000x1000x400`). Если
совпадения нет, товар всё равно создаётся, чтобы модель была доступна в
планировщике. Для обновления цен используйте `/admin/catalog` → товар → «Основное».

Повторный импорт в чистую БД требует исходных `models.zip`, `export.json` и
скриптов импорта; seed создаёт только базовый демонстрационный каталог.

### Оптимизация 3D-модели

В карточке товара, вкладка «3D-модель»:

- «Оптимизировать» запускает worker: STL/GLB → сварка вершин → упрощение → GLB.
  Для GLB с материалами/текстурами оптимизация сейчас создаёт упрощённую модель без
  материалов, UV и текстур. Оригинал сохраняется — его можно вернуть кнопкой «Откатить».

### Текстуры и материалы

- Для цветных моделей используйте **GLB** с внедрёнными PBR-материалами и текстурами.
- `.gltf` + отдельные `.bin`/картинки не подходят: загрузка принимает один файл.
- Verge3D-расширения `S8S_v3d_materials` не читаются three.js. Перед загрузкой
  экспортируйте модель из Blender в glTF Binary с обычными Principled BSDF-материалами
  или перенесите цвета в стандартный `pbrMetallicRoughness`.
- Материал с `extras.tintable = false` не перекрашивается выбранным RAL-цветом;
  так сохраняются дерево, столешница и чёрные детали.
- Оригинал сохраняется; планировщик автоматически берёт облегчённую модель.
- Цель по умолчанию — 50 000 треугольников. Для тяжёлых моделей появляется
  предупреждение.
- «Вернуть оригинал» отключает оптимизированный файл без удаления оригинала.
- Статус и ошибки видны в карточке; повторный запуск возможен после завершения.

## Заказы

`/admin/orders` — список с фильтрами по статусу и поиском по номеру, имени,
телефону, e-mail. В карточке:

- позиции и снимок цен/опций на момент заказа;
- снимки 2D/3D, фронт и профиль;
- смена статуса с комментарием и историей;
- скачивание и пересборка PDF;
- удаление (admin) — безвозвратное, с подтверждением.

Статусы: `draft` → `saved` → `submitted` → `in_progress` → `done` / `cancelled`.
Клиент видит только свои заказы (гостевая сессия по подписанной cookie). PDF
неизменяем: пересборка создаёт новый файл из сохранённого снимка заказа.

## Настройки

`/admin/settings` — реквизиты компании, данные для PDF, НДС (включён в цену или сверху),
префикс и формат номера, лимиты. Настройки применяются к новым заказам; старые
остаются с прежними снимками.

## Пользователи

Создание и блокировка — через `/api/admin/users` или CLI. Пароли хранятся как
scrypt-хеш, в открытом виде не сохраняются. После блокировки активная сессия
перестаёт проходить проверку.

## Уведомления

При `submitted` сервер пытается отправить письмо на `MAIL_TO`. Без SMTP заказ
создаётся, а в лог пишется «SMTP не настроен — письмо пропущено». Проверьте
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`, `MAIL_TO`.

## Типовые операции

- **Добавить товар**: раздел → «+» → заполнить основное → сохранить → изображения →
  модель → свойства/опции.
- **Изменить цену**: карточка → «Основное» → цена → сохранить. Старые заказы не меняются.
- **Скрыть товар**: снять «Опубликован». В каталоге планировщика он исчезнет, история
  заказов сохранится.
- **Обработать заказ**: `/admin/orders` → «Открыть» → статус «В работе» → комментарий →
  сохранить; PDF доступен в карточке.
